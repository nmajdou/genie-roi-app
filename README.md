# Genie ROI app

A [Databricks App](https://docs.databricks.com/aws/en/dev-tools/databricks-apps/) that measures the adoption,
engagement, quality and estimated ROI of **AI/BI Genie spaces** and **Genie Code**, using only Databricks
system tables. It follows the approach in
[Measure Genie Code impact](https://docs.databricks.com/aws/en/genie-code/impact) and extends it to Genie spaces.

## What it shows

| Tab | KPIs |
|---|---|
| **Overview & ROI** | Active users, questions and interactions, positive feedback rate, hours saved, value, cost, ROI, survey-based estimate |
| **Genie spaces** | Daily questions and users, new vs returning monthly users, thumbs up/down, regeneration and failure rates, per-space table (usage, feedback, SQL success rate, latency, data read), top users, curation effort, estimated compute cost |
| **Genie Code** | Daily interactions and users, new vs returning monthly users, usage by workspace, top users |
| **Methodology** | Definition and source of every KPI, value model, limitations, recommended survey |

The value model uses assumptions you set in the sidebar (minutes saved, hourly cost, analyst deflection), and
every number shows how it was calculated. See [METHODOLOGY.md](METHODOLOGY.md).

## Data sources

| System table | Used for |
|---|---|
| `system.access.assistant_events` | Genie Code usage |
| `system.access.audit` (`service_name = 'aibiGenie'`) | Genie spaces questions, conversations, feedback, curation |
| `system.query.history` | SQL generated by Genie (`query_source.genie_space_id`) |
| `system.billing.usage`, `system.billing.list_prices` | Estimated Genie warehouse cost |

System tables hold data for all workspaces in the account, so the app does too by default. Use the
*Workspace id* filter to scope it.

## Prerequisites

1. **System tables enabled** for the `access`, `query` and `billing` schemas (account admin).
2. **A SQL warehouse** (serverless recommended) for the app to query.
3. **Grants for the app's service principal.** After you create the app, a metastore admin runs:

   ```sql
   GRANT USE CATALOG ON CATALOG system TO `<app-service-principal-application-id>`;
   GRANT USE SCHEMA ON SCHEMA system.access TO `<app-service-principal-application-id>`;
   GRANT USE SCHEMA ON SCHEMA system.query TO `<app-service-principal-application-id>`;
   GRANT USE SCHEMA ON SCHEMA system.billing TO `<app-service-principal-application-id>`;
   GRANT SELECT ON TABLE system.access.audit TO `<app-service-principal-application-id>`;
   GRANT SELECT ON TABLE system.access.assistant_events TO `<app-service-principal-application-id>`;
   GRANT SELECT ON TABLE system.query.history TO `<app-service-principal-application-id>`;
   GRANT SELECT ON TABLE system.billing.usage TO `<app-service-principal-application-id>`;
   GRANT SELECT ON TABLE system.billing.list_prices TO `<app-service-principal-application-id>`;
   ```

   The service principal's application id is shown on the app's **Authorization** tab.

> The app shows user emails (top users). Restrict who can use the app (app permissions: `CAN USE`) to the
> people allowed to see this data.

## Deploy

### Option A: Databricks Asset Bundle

```bash
databricks bundle deploy --var warehouse_id=<warehouse-id>
databricks bundle run genie_roi
```

### Option B: Databricks CLI

```bash
databricks apps create genie-roi
# In the UI: Apps > genie-roi > Edit > add a "SQL warehouse" resource with key `sql-warehouse` (Can use)
databricks sync . /Workspace/Users/<you>/genie-roi
databricks apps deploy genie-roi --source-code-path /Workspace/Users/<you>/genie-roi
```

Then apply the grants above and open the app URL.

## Run locally

```bash
pip install -r requirements.txt
export DATABRICKS_CONFIG_PROFILE=<profile>   # or DATABRICKS_HOST + DATABRICKS_TOKEN
export DATABRICKS_WAREHOUSE_ID=<warehouse-id>
streamlit run app.py
```

Locally, the queries run with your own identity and permissions.

## Limitations

* Value and ROI figures are estimates driven by your assumptions. Calibrate them with a survey or time study.
* Compute cost uses list prices and splits shared warehouse cost by execution time.
* `assistant_events` counts before 7 May 2026 include background requests and are inflated.
